Этот файл предназначен для следующего разработчика/Claude. Он описывает фактическое состояние проекта, уже сделанные функции и незавершённую текущую задачу.

## 1. Проект

- Рабочая папка: C:\Users\aanto\Documents\Codex\2026-08-05\d\outputs\tg_account_shop_bot

## 3. Что уже работает в базовой версии

### Пользовательская часть

- /start предлагает китайский, английский и русский язык inline-кнопками.
- После выбора язык сохраняется в SQLite и применяется к меню.
- Inline-меню содержит каталог, кошелёк, профиль, рефералы, очередь, поддержку, язык и условия.
- Публичное меню команд Telegram содержит только пользовательские команды; admin-команды не публикуются.
- GPT Plus: NW/FW.
- Pro: 5x NW/20x NW.
- Queue поддерживает выбор количества.
- Есть покупка одной или нескольких позиций.
- Есть оплата через Crypto Pay и кнопка оплаты с баланса, если баланса хватает.
- Есть /balance, пополнение от $1.30, быстрые суммы и произвольная сумма в валюте выбранного языка.
- После успешной оплаты баланс обновляется автоматически.
- Реальные цифровые данные выдаются только из таблицы goods через delivery_payload; порядок выдачи случайный, при покупке нескольких позиций выдаётся нужное количество разных payload.
- Заказы без доступных реальных данных переходят в waiting_stock; бот не должен выдумывать рабочие аккаунты или выдавать несуществующие credentials.
- Queue/waitlist хранится в SQLite и уведомляет пользователя, когда товар реально доступен.
- Help содержит поддержку, оферту и privacy policy.

### Админская часть, которая была до текущей задачи

- /admin показывает админ-панель.
- /stock показывает склад.
- /add_good <product_key> <payload> добавляет реальный цифровой товар.
- В админке можно просматривать пользователей и подробную статистику воронки: входы, каталог, checkout, способы оплаты, оплаты, пополнения, ручные платежи, рефералы и очередь.
- Админка управляет категориями, товарами, названиями, ценами и единым наличием. Цена вводится только в USD, остальные валюты пересчитываются автоматически по курсам настроек.
- Можно вручную пополнять баланс пользователя; уведомление самому пользователю не отправляется.
- До текущих изменений пополнение баланса принимало Telegram ID, требовалось расширить до username.
- Администраторы задаются через ADMIN_IDS.
- При /start администраторы получают уведомление о новом пользователе.

### Безопасность и сохранность

- SQLite и логи сохраняются зашифрованным архивом в GitHub Actions cache.
- Секреты не должны быть прописаны в исходниках, commit message, PR body, shell command или tg-shop.md.
- Не просить у владельца seed-фразу Trust Wallet, приватные ключи, 2FA-коды или bot/payment tokens.

## 4. Требования текущей задачи

### Админ-панель

Нужно довести админку до полного управления без правки кода:

1. Управление складским счётчиком:
   - добавить/убавить количество товара кнопками или вводом числа;
   - не требовать ввода содержимого товара для изменения отображаемого количества;
   - отдельно оставить добавление реальных payload через /add_good/админку;
   - покупателю и в основном экране склада показывать только единый счётчик;
     внутренние payload не выдавать как второй «реальный» остаток.
2. Пополнение баланса по @username и по числовому ID.
3. Управление товарами:
   - создание нового товара с key, категорией и названиями на RU/EN/ZH;
   - редактирование цен из админки;
- цена-источник только в USD; RUB/CNY/VND/INR вычисляются автоматически по курсам;
   - новые товары должны появляться в пользовательском каталоге и участвовать в оплате/складе.
4. Не перезаписывать цены, добавленные администратором, при следующем запуске. Базовые товары можно только seed-ить через INSERT OR IGNORE.

### Пользовательский интерфейс

- Inline-кнопки **поддерживают** цвет: Bot API 10.2 добавил поле `style` у
  `InlineKeyboardButton` и `KeyboardButton` со значениями `success` (зелёная),
  `danger` (красная), `primary` (акцентная). Проверено на aiogram 3.30.0,
  `aiogram.enums.ButtonStyle`. Требует `aiogram>=3.30` — на более старых
  версиях поле не существует и запрос падает на валидации.
  Дополнительно есть `icon_custom_emoji_id` — кастомная эмодзи-иконка кнопки.
  Использовать цвет по смыслу, плюс дублировать маркерами в тексте
  (старые клиенты цвет игнорируют, текст видят все):
  - 🟢 `success` — эффективное наличие больше нуля;
  - 🔴 `danger` — наличие равно нулю.
- Добавить каталог товаров для новых позиций.
- Добавить раздел Settings с включением/отключением уведомлений о покупках.

### Реальные уведомления

- При фактическом пополнении склада отправлять всем зарегистрированным пользователям сообщение на их языке: склад пополнен, добавлены новые аккаунты; без перечисления конкретных товаров.
- При фактически подтверждённой покупке отправлять подписанным пользователям сообщение с товаром, количеством, ценой и покупателем.
- Покупателя маскировать: первые 3 символа username/ID и ***.
- Под сообщением всегда должна быть inline-кнопка отключения уведомлений.
- Настройка должна храниться в SQLite, а не в MemoryStorage.
- Балансные пополнения не считать покупкой товара.

### Crypto Wallet manual payment

Нужно добавить отдельный способ пополнения после выбора суммы:

1. Сначала пользователь выбирает сумму.
2. Затем видит варианты Crypto Pay и Cryptocurrency.
3. Crypto Pay оставляет текущий автоматический invoice-flow.
4. Cryptocurrency показывает выбранный актив/сеть, публичный адрес, сумму в криптовалюте и инструкцию.
5. У каждого USDT/USDC варианта обязательно указывать сеть: TRC20/ERC20/BEP20/TON/Solana и т. п.
6. Не считать ручной перевод оплаченным автоматически без blockchain-проверки или ручного подтверждения администратором. До подтверждения заказ/баланс остаётся pending.
7. Если используется уникальная дробная часть для сверки, она должна быть явно показана покупателю и не должна добавляться скрытно. Нужны точность, курс, время курса и сеть.

Важно: файл с адресами из Downloads не является частью GitHub Actions автоматически. Для production нужно либо перенести только проверенные публичные адреса в репозиторий/config, либо хранить их в GitHub Secrets/защищённом хранилище. Seed/private keys туда не добавлять.

## 8. Актуальное решение по последней задаче

- Пользователь попросил сделать всё, кроме симуляции. Fake/simulated покупки,
  пополнения и рекламные события не реализуются и не должны появиться позже.
- Не генерировать похожие логины/пароли и не выдавать их как реальные товары.
  Выдача работает только с payload, который администратор сам загрузил в
  `goods`; виртуальное наличие может создавать очередь предзаказов, но не
  создаёт фиктивные credentials.
- В интерфейсе покупателя покупатель не получает уведомление о собственной
  покупке; уведомления о чужих покупках можно выключить в Settings.
- Кнопка прямой оплаты называется `Cryptocurrency`, под ней используется
  `Проверить оплату`; автоматическое зачисление без проверки администратором
  не выполняется. Сначала используется live-курс Crypto Pay, затем явно
  датированный fallback из `crypto_fallback.py`.
- После изменения цены админ вводит одно значение USD. `sync_runtime_products`
  пересчитывает цены в локальных валютах из `currency_rates`, поэтому старые
  региональные значения не возвращаются после рестарта.
- В `/admin` есть отдельная `📢 Рассылка`: администратор вводит обычный текст,
  получает предпросмотр и число зарегистрированных получателей, затем вручную
  подтверждает отправку. Ошибки заблокированных чатов считаются отдельно и не
  останавливают рассылку.
- Реферальная ссылка имеет вид `https://t.me/<bot>?start=ref_<telegram_id>` и
  доступна в разделе `Рефералы`/команде `/invite`. Новый пользователь
  привязывается к пригласившему только при первом `/start`; самоприглашение
  блокируется. При каждом оплачиваемом заказе рефереру начисляется 15% от
  канонической USD-стоимости на баланс, включая Crypto Pay, Cryptocurrency
  после подтверждения админом и оплату с баланса. Пополнение баланса не считается
  покупкой. Начисление идемпотентно по `order_id`, поэтому повторные попытки не
  дублируют кешбэк и сопровождаются уведомлением рефереру.

### Дополнительные реализованные возможности

- В карточке каждого товара администратор может установить индивидуальную
  скидку от 0 до 99%. В SQLite хранится процент, покупатель видит старую и новую
  цену, а в заказ записывается уже сниженная USD-стоимость; локальные валюты и
  оплату с баланса используют ту же сумму.
- Реферальная акция активна с 22 августа по 5 сентября 2026 UTC: если
  приглашённый пользователь совершает оплаченные покупки на суммарные $5,
  пригласившему один раз начисляется дополнительный $1. Награда хранится в
  referral_campaign_rewards с уникальным ключом кампании и не дублируется при
  повторной обработке заказа.
- В поддержке есть тикеты: пользователь открывает обращение из кнопки Support,
  отправляет сообщение и может продолжить переписку; администраторы получают
  уведомление, видят отдельный раздел /admin → Тикеты поддержки, отвечают и
  закрывают тикет. История хранится в support_tickets и support_messages.

### Текущее состояние после последнего обновления

- Прямая ссылка/username внешней поддержки удалены из пользовательского интерфейса.
  В разделе Help/Support остаётся только кнопка встроенного тикета; оферта и политика
  открываются отдельными ссылками.
- Публичные номера тикетов, заявок Cryptocurrency и заказов — стабильные случайные
  пятизначные значения. Внутренние SQLite ID сохраняются только для callback-ов и связей.
  При миграции старые записи получают такие номера автоматически.
- Очередь динамически зеркалит категории и товары из Products. Категории, товары,
  навигация очереди и выбор количества используют синие inline-кнопки.
- Описание товара необязательно: оно показывается покупателю только если задано.
  В админке описание редактируется кнопкой «Описание», а `/clear` удаляет его.
- В админке есть глобальный переключатель уведомлений о покупках для всех пользователей.
  Персональные отключения сохраняются; покупателю собственная покупка не рассылается.
- Статистика считается с сохранённой точки сброса и исключает все Telegram ID из
  `ADMIN_IDS`; кнопка «Обнулить статистику» меняет только точку отсчёта и не удаляет историю.
- Цена товара вводится администратором только в USD. После синхронизации runtime цена
  автоматически пересчитывается в валюты языка по настроенным курсам.

## 9. Рекомендуемый порядок работы Claude

1. Прочитать этот файл и git diff.
2. Закончить handlers и main() sync, не перезаписывая текущие пользовательские изменения.

4. Проверить Telegram callback-data длиной до 64 bytes.
5. Проверить git diff --check, compile и mock payment test.
6. Создать отдельную ветку, commit только исходники/конфиги без секретов.
7. Создать PR, проверить diff, merge в main.
8. Проверить наличие секретов только по именам через GitHub CLI; значения не читать.
9. Запустить workflow вручную и убедиться, что шаги decrypt/install проходят, а Run bot остаётся активным.
